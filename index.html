Shield Engineering

The visual language for Shield Legal's operations software: modern, professional, and a little bit warm.
v0.8 · pre-1.0 draftClose to 1.0, not there yet.

Overview

What this is

The style guide for the software Shield Engineering builds. Engineers use it as the reference for colors, type, spacing and components, with the class and token names. Everyone else can use it to see why our products look the way they do.

Why it looks like this

Shield Legal delivers mass tort, personal injury and other legal-related data to law firms and their funding partners. Those relationships depend on precise, signed agreements, so the interface has to make status unmistakable and feel calm and trustworthy to people reviewing documents with legal weight.

Design principles

Modern, but professional. Clean type, generous spacing and soft rounded controls, with a tone suited to legal work. Legible first. Text and status colors are tuned for contrast, because misreading a term or a status is costly. Consistent. One set of tokens drives everything. Easy to change. Each visual decision lives in a named token or a short CSS rule.

Light mode

Modern and professional, with a hint of warmth. The page is a faint warm white (#FFFBF7), like the pages of a novel or an old legal pad, and cards stay pure white so content sits on the page like sheets of paper. Text is solid black, like ink. The warmth stays subtle so it never looks yellowed in a modern technical product.

Dark mode

Modern and technical, but not harsh. The goal is comfort: think of a well-lit night under a full moon, not a terminal. The page is a deep midnight blue (#0B1220) instead of black, cards sit just above it in a slightly lighter navy, and text is a warm off-white (#FFFBF7) that stays easy to read, so long sessions stay easy on the eyes.

How it is built

Plain HTML, CSS and JavaScript, no UI framework and no build step. tokens.css holds the values (colors, fonts, spacing, radius, shadow, motion) and components.css holds the components that use them. shield.js adds the interactions on this page. Classes are prefixed shield-. Everything below is a working component: open the select, flip the switch, dismiss a tag, push a toast.

Engineers: switch on Engineer Mode at the top of the sidebar. A code panel appears at the end of each section with copy-paste HTML and the tokens involved.

Type sizes

Four sizes cover body copy and everything inside the components. 16px is the base because 14px is too small for most people to read comfortably for long. Change a number in tokens.css to resize that role everywhere.

Small text: --weight-small

Satoshi looks light at small sizes, so small text and control labels (buttons, tabs, menu items, tags, table cells, captions, alerts, toasts, step titles, stat labels) use --weight-small (500) instead of 400. Paragraphs and typed input text stay at 400. Change that one token to adjust all of it.

Motion

Motion tells people that something changed: a button reacted, a menu opened, a message arrived. In Shield products it is small and fast. Pick a duration by what is changing, never by what feels nice: there are four durations, two easings, and a rule for when to use each.

How to use it

  1. Something small changes in place (hover, focus, checked, a chevron turning): --duration-fast with --ease-standard.
  2. Something appears (modal, toast, popover, drawer): --duration-base. Use --ease (fast start, soft landing) for things that slide in, --ease-standard for things that fade in.
  3. Something leaves. Components here hide without an animation. If you add one, make it shorter than the way in: --duration-fast.
  4. Animate only color, background-color, border-color, opacity, box-shadow and transform. Do not animate width, height, margin, top or left: neighbors jump.
  5. Never make anyone wait. Nothing should be disabled or hidden while an animation plays. Nothing should take longer than --duration-slow (0.25s).
  6. Never type a number. Write var(--duration-fast), not 0.15s.
  7. Reduced motion is automatic. People who ask their OS for less motion get near-instant transitions from tokens.css; never override it.

Rules

For reflow, touch target size and content that appears on hover or focus, Shield follows the W3C's Web Content Accessibility Guidelines (WCAG) 2.2, Level AA. Read the criteria themselves rather than a summary:

  • SC 1.4.10 Reflow: content works at 320 CSS pixels wide without scrolling in two directions.
  • SC 2.5.8 Target Size (Minimum): pointer targets are at least 24 by 24 CSS pixels.
  • SC 1.4.13 Content on Hover or Focus: content that appears on hover or focus can be dismissed, hovered over, and stays until dismissed.

Date picker

A date field is the browser's own date input styled as a normal text field. That keeps it fully keyboard and screen-reader friendly, shows the calendar in the visitor's language and format, and costs nothing to maintain. Type the date, use the arrow keys, or open the calendar from the icon. Say the expected format in the hint when typing matters, and use two fields for a range.

What it is and how to get it

The native HTML date input, <input type="date">. It is built into every browser, so there is nothing to install: add the element and the shield-input class. The calendar popup is drawn by the browser, so it looks different from browser to browser and cannot be restyled. People see the date as MM/DD/YYYY (US browsers follow the visitor's language settings). Your code reads and writes the value as YYYY-MM-DD, which follows the ISO 8601 standard (as HTML uses it) and is how the element passes it along, not what is shown on screen. It is a plain calendar date with no time or time zone.

Toast

A brief confirmation, for example "Saved". Pushed from code with useToast(), shown top-center, and gone after 3 seconds. Use an Alert if the message needs to stay.

Tooltip

A short, non-interactive explanation that appears when a control is hovered or focused. It is for extra information: if people need it to complete the task, put it on the page. Keep it to a sentence or two, never put links or buttons inside (use a Popover for that), and make it work from the keyboard. It stays open while the pointer is over it and Escape dismisses it, as WCAG 1.4.13 requires. Hover or tab to the examples.

Popover

A small panel opened by a click that holds a title, a few lines of text and, if needed, buttons. Use it for explanations with a next step ("Why is this locked?" with a Create change request button) or a quick choice that doesn't deserve a modal. It closes when you click the trigger again, click outside, press Escape (focus goes back to the trigger), or use one of its buttons. Don't put forms or long content in it: that is a Drawer or a Modal.

Popover or tooltip?

If the person only needs a hint, use a tooltip. If they need to read something longer or take an action, use a popover.

Steps

Shows progress through a multi-stage process, such as creating an offer. Each step is not started, in progress (half-filled dot) or done (checkmark). The step you are looking at is marked separately with a bold title and a soft ring, so going back to an earlier step never changes a later step's state.

Pagination

Splits a long list into pages. Always show the first and last page, the current page and its neighbors, with an ellipsis for the gap, plus Previous and Next and a plain "1–10 of 118" summary. Use it for tables and lists that are too long to scroll comfortably; for a short list, show everything. After changing page, focus stays on the control and the summary is announced to screen readers.

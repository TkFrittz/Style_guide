Shield Engineering

The visual language for Shield Legal's operations software: modern, professional, and a little bit warm.

Overview

What this is

The style guide for the software Shield Engineering builds. Engineers use it as the reference for colors, type, spacing and components, with the class and token names. Everyone else can use it to see why our products look the way they do.

Why it looks like this

Shield Legal delivers mass tort, personal injury and other legal-related data to law firms and their funding partners. Those relationships depend on precise, signed agreements, so the interface has to make status unmistakable and feel calm and trustworthy to people reviewing documents with legal weight.

Design principles

Modern, but professional. Clean type, generous spacing and soft rounded controls, with a tone suited to legal work. Legible first. Text and status colors are tuned for contrast, because misreading a term or a status is costly. Consistent. One set of tokens drives everything. Easy to change. Each visual decision lives in a named token or a short CSS rule.

Light mode

Modern and professional, with a hint of warmth. The page is a faint warm white (#FFFBF7), like the pages of a novel or an old legal pad, and cards stay pure white so content sits on the page like sheets of paper. Text is solid black, like ink. The warmth stays subtle so it never looks yellowed in a modern technical product.

Dark mode

Modern and technical, but not harsh. The goal is comfort: think of a well-lit night under a full moon, not a terminal. The page is a deep midnight blue (#0B1220) instead of black, cards sit just above it in a slightly lighter navy, and text is a warm off-white (#FFFBF7) that stays easy to read, so long sessions stay easy on the eyes.

How it is built

Plain CSS and small React components, no UI framework. tokens.css holds the values (colors, fonts, spacing, radius, shadow) and components.css holds the components that use them (the app's copy is src/styles/ui.css). Classes are prefixed shield-. Everything below is a working component: open the select, flip the switch, dismiss a tag, push a toast.

Four status colors that mean the same thing everywhere. Success: approved, active, completed. Warning: waiting on someone, such as a signature or addendum. Error: rejected, canceled, destructive. Info: internal work in progress, such as review or pricing. Each has a text color, a background and a border, used together. In light mode, text on its background measures 7.2:1 (success), 7.8:1 (warning), 5.3:1 (error) and 4.9:1 (info), all above the 4.5:1 readability target. In dark mode only success clears it (4.8:1); warning (3.4:1), error (2.7:1) and info (3.2:1) do not and should be revisited. Info uses blue-9 text in light mode and blue-8 in dark.

Typography

Headings and the brand mark use Fraunces, a soft serif with a book-like, editorial voice that nods to printed legal documents. Body text and every control use Satoshi, a clean modern sans-serif that stays clear at small sizes. Both are variable fonts hosted in the fonts/ folder, so nothing depends on a network request. If they fail to load, headings fall back to Georgia and body text to the system sans-serif.

Type sizes

Four sizes cover body copy and everything inside the components. 16px is the base because 14px is too small for most people to read comfortably for long. Change a number in tokens.css to resize that role everywhere.

bodyReading text: paragraphs, modal text, card titles--font-size-body · 16px
controlText inside controls: buttons, inputs, tabs, menu items--font-size-control · 15px
smallSecondary content: table cells, alerts, toasts, step titles--font-size-small · 14px
captionSmallest readable text: tags, pills, stat labels, hints--font-size-caption · 13px

Small text: --weight-small

Satoshi looks light at small sizes, so small text and control labels (buttons, tabs, menu items, tags, table cells, captions, alerts, toasts, step titles, stat labels) use --weight-small (500) instead of 400. Paragraphs and typed input text stay at 400. Change that one token to adjust all of it.

400Regular weight at 12.5px: thin and harder to readnot used for small text
500Small-text weight at 12.5px: what the components use--weight-small

Button Live

Use Primary (solid blue) once per screen for the main action. Default is for ordinary actions, Dashed for "add something", Text for low-emphasis actions like Cancel, Link for text-style navigation, and Danger for destructive actions (Danger (default) is the quieter outline version). Buttons are pill-shaped (42px), and only Primary and solid Danger have a soft shadow. Primary is blue-7 (#0A85C7), darkening to blue-8 on hover. White text on blue-7 measures 4.0:1, a little under the 4.5:1 target. Colors come from tokens.css.

Avatar & Badge

An avatar is a colored circle with initials. A dot badge on its corner means "needs attention". A count badge is a small number, such as an unread count beside a menu item.

Avatar: sizes JT JT JT

24 dense rows & table cells   32 default, headers, menus, most lists   40 profile headers & detail panels   icon fallback no name/initials yet, e.g. an unassigned contact

Badge: dot JT

A corner-overlaid marker with no number, means "something here needs attention," not "how many." Always paired with an avatar or icon, never used on its own.

Badge: count Notifications3

Unlike the dot, count doesn't corner-overlay anything, it renders as a plain inline chip meant to sit right after a label. This is the exact markup behind the "Offers" count in the Menu section below.

Skeleton & Spin

Loading states. A skeleton is a placeholder shaped like the content that is loading. A spinner shows an action in progress, and inside a button it takes the button's text color.

Toast Live

A brief confirmation, for example "Saved". Pushed from code with useToast(), shown top-center, and gone after 3 seconds. Use an Alert if the message needs to stay.

Shows progress through a multi-stage process, such as creating an offer. Each step is upcoming, current (outlined) or done (filled with a checkmark).
